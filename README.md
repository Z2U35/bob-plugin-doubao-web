# 豆包网页翻译 · Bob 插件

让 Bob 使用豆包网页端翻译。**不需要 API Key**，支持豆包、豆包·火山、豆包·微软三种翻译选项。默认由用户在自己的浏览器登录并填写 Cookie，**不需要安装或运行额外程序**；原有 Mac 登录助手保留为备选。

> **v0.2.1 私有测试预览版，非官方作品。** 尚未完成真实账号在 Bob 内翻译成功的人工验收，暂不公开仓库。离线模拟测试不等同于真实账号验证。网页端协议、登录入口及 WebKit 兼容性可能变化，不能保证任何账号都能使用。

## 安装

<a id="manual-cookie"></a>

### 推荐：自己在浏览器登录，手动填写 Cookie

1. 下载并双击 `.bobplugin` 文件，在 Bob 中添加「豆包网页翻译」文本翻译服务。
2. 保持默认的 **「手动 Cookie（推荐，无需助手）」**。如果从 0.2.0 升级，Bob 可能保留原来的选项，请自行切换；插件不会覆盖你已选定的助手模式。
3. 在常用浏览器打开 [豆包官网](https://www.doubao.com/)，按官方页面提示扫码或用其他官方方式完成登录。也可先在 Bob 留空 Cookie 点「验证」，再点击错误提示中的帮助链接打开官网。
4. 打开浏览器的开发者工具，选择 **Network / 网络**，再刷新豆包页面。
5. 选择一条已经实际发往 **`https://www.doubao.com/`** 的请求，在 **Headers / 标头 → Request Headers / 请求标头 → Cookie** 中复制完整值。若该请求没有 Cookie，换一条登录后发出的同域请求。
6. 把完整值粘贴到 Bob 的 **「Cookie（手动模式必填）」** 输入框，先选择「豆包翻译」，然后点「验证」。验证会向豆包发送固定测试句 `Hello, world!`。
7. 验证通过后即可划词或使用你原有的 OCR 服务识别后翻译。Cookie 失效后，重新登录官网、复制新值、替换旧值并再次验证。

**到底复制哪一个？** 不要从 Application / 应用里的 Cookie 表格挑某一个值；应复制请求头 `Cookie` 的完整单行值，形如 `名称=值; 另一个名称=值`。不需要自己逐项拼接，也不要复制响应头 `Set-Cookie`、完整 cURL、JSON 或整段请求头。插件也接受一行开头带 `Cookie:` 的值。

User-Agent 通常留空；确有需要时，从同一个浏览器的请求头复制 `User-Agent` 的值填写，不要包含换行。

**Cookie 就是登录凭证，不要发到聊天、GitHub Issue、截图或公开日志里。** 本插件不要求把 Cookie 上传给开发者。不要用 `document.cookie` 代替上述步骤，它可能漏掉 HttpOnly 登录凭证。

手动模式不会访问助手端口、读取助手配对文件或自动切换到助手里的账号，Cookie 为空、格式错误或过期时也不会回退。**不必安装、启动或配对登录助手。**

<a id="login-helper"></a>

### 备选：原有 Mac 登录助手

如果不方便自己找 Cookie，可以选择原有的助手方案：

1. 下载并解压 **Doubao Login Helper 0.2.0**，把 `.app` 拖到「应用程序」后打开。已经安装的用户继续使用原版本即可。
2. 在助手窗口里的 **豆包官方网站** 登录。官网提供扫码时扫码；若要求手机号或验证码，按官网提示完成。助手不提供自制二维码，也不会绕过登录或设备确认。
3. 在 Bob 把「登录方式」改为 **「登录助手（备选）」**。此模式不使用手动填写的 Cookie 或 User-Agent，可以留空。
4. 点 Bob 的「验证」。首次连接会出现 **6 位配对码**，助手也会显示相同的码。核对一致后，在助手中点击「允许配对」。**若不是自己刚刚发起的验证，不要允许。**
5. 回 Bob 再点一次「验证」。插件会读取助手登录态，并发送 `Hello, world!` 到豆包测试翻译。已有配对会保留，无需因切换模式重新配对。

使用助手模式时，助手需保持运行。关掉登录窗口不会退出助手，菜单栏仍有「豆包登录」；选择「退出登录助手」才会停止本机连接。没有默认添加开机启动项。切回手动模式不会删除助手登录态或配对信息，但不再使用它们；需要清除时可在助手菜单自行操作。

**macOS 提示无法验证开发者？** 当前助手只有 ad-hoc 签名，没有 Apple Developer ID 签名或公证。请先核对来源、源码和校验值，再按系统「隐私与安全性」提示处理。不要全局关闭 Gatekeeper；也可以直接使用推荐的手动模式。

### 登录方式与升级兼容

| 登录方式 | Cookie 有值 | Cookie 为空 |
| --- | --- | --- |
| 手动 Cookie（默认、推荐） | 使用填写的 Cookie | 给出官网登录和复制指引，不连接助手 |
| 登录助手（备选） | 忽略手动值，使用助手 | 使用助手 |
| 自动选择（兼容旧版） | 优先使用手动值；失效也不回退 | 使用助手，需先安装、运行并配对 |

保留第三项是为了兼容 0.2.0 已保存的 `auto` 选项；新用户无需选择它。没有登录方式配置时，运行逻辑与设置界面均默认手动模式。

**自动化边界：** Bob 没有公开的“插件设置打开时启动浏览器”钩子。本插件提供验证错误中的官网链接，由用户点击，不会自动弹出浏览器或读取现有浏览器的 Cookie。手动模式需要复制粘贴；助手模式需要另装程序、官方登录和首次配对。

## 如何工作

- 推荐的手动模式从 Bob 设置读取你填写的 Cookie，直接访问豆包，不依赖本机助手。
- 登录助手使用独立、非持久化的 `WKWebView` 打开豆包官网，不读取 Chrome、Edge、Safari 的现有 Cookie 数据库。
- 仅将助手窗口产生的豆包 Cookie 保存在 **macOS 钥匙串**。恢复时保留 Secure / HttpOnly 属性。
- Bob 与助手首次通过可见确认配对；后续使用随机 256 位本机令牌访问固定的 `127.0.0.1:17643`。
- 助手把适用于豆包翻译地址的 Cookie 和当前 WebView User-Agent 提供给已配对的 Bob。
- **原文仍由 Bob 直接发给豆包 HTTPS 接口**，不经过助手转发，更没有第三方翻译中转服务器。
- 插件解析豆包 SSE 事件，把译文转为 Bob 1.21 的纯文本显示格式。

助手不是密码管理器。登录态和本机配对令牌都是敏感信息；详见 [SECURITY.md](SECURITY.md)。官方网页本身可能加载其登录与 CDN 资源。

## 功能与限制

- 三种翻译服务可切换；是否可用取决于账号和上游服务。
- 支持简繁中文及英、日、韩、法、德、西、葡、俄、意、阿、泰、越、印尼、马来、土耳其、荷兰、波兰语。
- 支持取消、超时、SSE 接收、UTF-8 跨包处理及中文错误提示。
- 上游按条目返回译文，不保证逐字输出；保留上游输出的换行，不渲染 Markdown。
- 单次安全上限 12000 个 UTF-16 字符，部分 emoji 占两个；这是插件限制，不是官方额度声明。
- 登录失效时，助手模式会尝试打开官方登录页；仍需你本人完成扫码/验证，不会代输密码或绕过验证。
- 不是通用聊天 API，不支持自由问答、自定义模型或系统提示词。
- Bob 的 OCR 服务不受本插件替换。
- 不保证无限次数、长期可用或规避服务条款与账号限制。

## 故障排查

| 提示 | 处理 |
| --- | --- |
| Cookie 未填写 / 格式不正确 | 在自己的浏览器登录，按「推荐方案」复制完整请求头 Cookie，粘贴后再次验证。 |
| `710012000` / `710012001` / `710022013` | 登录失效；手动模式重新登录并替换 Cookie，助手模式在助手里重新登录。 |
| 助手未启动 / 无法连接 | 只影响助手相关模式；可以切回手动 Cookie，或打开 Doubao Login Helper。 |
| 配对码 | 核对 Bob 和助手两处相同的 6 位码，允许后再次验证。 |
| 配对已失效 | 可能在助手中撤销了授权；重新验证并确认。 |
| 需要登录 | 在助手官方页面完成登录，再验证；“检测到凭证”不等于账号已通过翻译验证。 |
| HTTP 403 / 官方页面不兼容 | 先确认官网可用；助手内无法登录时改用手动模式。 |
| `710012007` / `676010003` / HTTP 429 | 请求过频或服务繁忙，稍后重试。 |
| `710022002` / `710022004` | 上游拒绝请求；检查内容或稍后重试。 |
| 17643 端口占用 | 退出重复的助手；不要把 Cookie 填到陌生程序提供的替代端口。 |

助手菜单提供「清除本机登录」和「撤销 Bob 配对」。清除本地 Cookie 不等于撤销豆包服务器上所有设备的会话；涉及凭证泄露时应使用豆包账号自身的退出/会话管理功能。

如果你用过本地定制的 0.1.0：0.2.x 使用新的插件 identifier，属于新插件。安装并验证新服务后，再自行停用旧服务；不会擅自修改旧配置。0.2.0 升级到 0.2.1 则保持同一个 identifier。
